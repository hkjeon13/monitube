# Video ID 기반 영상 탐색, 로딩 표시 및 키워드 분석 개선 계획

## 1. 문서 상태

- 상태: 구현 완료, 운영 배포 대상
- 대상: 채널 영상 조회, 키워드 영상 검색, 소스 목록 로딩 UI, 수집 현황 표, 분석 키워드 품사 필터
- 제외: 댓글 수집 provider 변경, 기존 영상 자동 삭제, 키워드 검색 결과의 전체 수집률 계산

## 2. 목표

다음 문제를 해결한다.

1. 소스 목록을 불러오는 동안 빈 목록이나 `0개`가 먼저 표시되어 DB가 초기화된 것처럼 보이는 문제
2. 채널의 최신 페이지가 모두 기존 영상이라는 이유로 과거의 누락 영상을 확인하지 못하는 문제
3. 영상 개수만 비교하여 중복, 삭제, 순서 변경을 정확히 구분하지 못하는 문제
4. 키워드 검색 결과가 유동적인데도 전체 결과를 확정적인 모집단처럼 취급하는 문제
5. 분석 키워드에 의미가 약한 동사 원형이 포함되어 핵심 주제를 파악하기 어려운 문제

핵심 원칙은 다음과 같다.

- 저장 여부와 중복 여부는 YouTube Video ID로 판단한다.
- 채널의 공개 영상 수는 과거 누락 보정을 시작할지 판단하는 조건으로만 사용한다.
- 키워드 검색 결과 개수는 완료율이나 과거 누락 보정 기준으로 사용하지 않는다.
- 분석 키워드는 일반명사와 고유명사만 집계한다.

## 3. 확정된 동작

### 3.1 채널 영상 조회

매 자동 수집 및 수동 재수집에서 최신 1페이지는 항상 확인한다.

과거 누락 보정은 다음 조건을 만족할 때만 수행한다.

```text
채널 정보의 공개 영상 수
>
해당 채널 소스에 연결된 고유 YouTube Video ID 수
```

예를 들어 채널 정보에는 영상이 100개로 표시되고 현재 소스에 연결된 고유 영상이 30개라면 과거 누락 보정 대상이다.

최신 페이지에서 조회한 10개 Video ID가 모두 기존 30개에 포함되더라도, `30 < 100`인 동안에는 탐색을 종료하지 않고 다음 페이지를 조회한다.

페이지별 처리는 다음과 같다.

```text
page_video_ids = 현재 페이지에서 얻은 고유 Video ID 집합
known_video_ids = 이 채널 소스에 이미 연결된 Video ID 집합
new_video_ids = page_video_ids - known_video_ids
```

- `new_video_ids`만 신규 영상 수집 대상으로 등록한다.
- 기존 Video ID는 중복 작업을 만들지 않는다.
- 한 페이지가 모두 기존 Video ID라는 사실만으로 탐색을 종료하지 않는다.
- 공개 영상 수보다 수집한 고유 ID 수가 적은 동안에는 다음 페이지 토큰을 따라간다.
- 다음 페이지 토큰이 없거나 실행당 보정 페이지 제한에 도달하면 현재 실행을 종료한다.
- 보정 결과 고유 ID 수가 공개 영상 수 이상이 되면 이후 실행에서는 최신 1페이지만 확인한다.

### 3.2 채널 영상 수의 역할

채널의 공개 영상 수는 정확한 저장 완료 개수로 간주하지 않는다.

- 공개 영상 수는 과거 누락 보정 활성화 여부를 판단하는 참고 기준이다.
- 실제 신규·기존·중복 판정은 항상 Video ID로 수행한다.
- 채널 정보에서 영상 수가 감소해도 기존 저장 영상을 자동 삭제하지 않는다.
- 비공개·삭제·지역 제한 영상 때문에 숫자가 달라도 저장 데이터를 임의로 제거하지 않는다.

### 3.3 키워드 영상 검색

키워드는 채널과 다른 정책을 적용한다.

- 매 실행에서 최신순으로 조회한다.
- 조회 범위는 소스 설정의 `maxPagesPerRun`을 따른다.
- 각 페이지의 결과는 소스에 연결된 Video ID와 비교한다.
- 신규 Video ID만 영상 수집 대상으로 등록한다.
- 페이지 간 또는 실행 간 중복 Video ID는 중복 저장하거나 중복 작업으로 만들지 않는다.
- 검색 결과 수와 저장 영상 수를 비교하여 과거 누락 보정을 시작하지 않는다.
- 검색 결과의 순서와 개수는 실행마다 달라질 수 있으므로 전체 완료율을 계산하지 않는다.
- 중간 실패한 동일 작업은 마지막으로 성공한 체크포인트를 기준으로 재시도한다.
- 다음 자동 실행이나 별도 수동 재수집은 다시 최신 검색 범위부터 확인한다.

키워드 검색에는 채널 방식의 지속적인 과거 페이지 보정을 적용하지 않는다.

## 4. 체크포인트

### 4.1 채널

채널 누락 보정 중에는 다음 정보를 작업 체크포인트에 보관한다.

- 조회 중인 채널 ID
- 마지막으로 성공한 페이지 번호
- 다음 페이지 토큰
- 이번 실행에서 확인한 고유 Video ID 수
- 이번 실행에서 발견한 신규 Video ID 수
- 조회 시작 시점의 채널 공개 영상 수
- 조회 시작 시점의 소스 보유 고유 Video ID 수

실패 시 마지막으로 성공한 페이지 이후부터 동일 작업을 재시도한다. 이미 처리한 Video ID가 다시 반환되더라도 ID 기반 멱등 처리로 중복 작업을 만들지 않는다.

### 4.2 키워드

키워드 작업 체크포인트에는 다음 정보를 보관한다.

- 검색어
- 마지막으로 성공한 페이지 번호
- 현재 페이지 토큰
- 이번 실행에서 확인한 고유 Video ID 수
- 이번 실행에서 발견한 신규 Video ID 수

체크포인트는 동일 작업의 오류 재시도에만 사용한다. 다음 6시간 자동 실행이나 사용자가 새로 요청한 수동 재수집까지 과거 검색 토큰을 이어서 사용하지 않는다.

## 5. 실행 주기 및 제한

- 기본 자동 실행 주기: 기존 6시간 유지
- 수동 재수집: 사용자가 클릭하면 대기 시간 없이 즉시 실행
- 채널 최신 조회: 실행마다 1페이지
- 채널 과거 누락 보정: 공개 영상 수보다 수집한 고유 ID 수가 적을 때만 수행
- 채널 실행당 보정 페이지: 기본 최대 5페이지
- 키워드 조회 페이지: 기존 `maxPagesPerRun` 설정 유지

채널이 매우 큰 경우 한 번의 실행으로 모두 보정하지 않고 6시간 자동 실행 또는 수동 재수집을 통해 다음 구간을 이어서 처리한다.

## 6. 로딩 UI

### 6.1 최초 로딩

소스 목록 요청이 완료되기 전에는 다음 빈 상태 문구를 표시하지 않는다.

- 아직 등록된 키워드가 없습니다.
- 아직 등록된 수집 대상이 없습니다.
- 영상 0개
- 댓글 0개

대신 목록 영역에 스피너와 `수집 대상을 불러오는 중입니다.` 문구를 표시한다.

### 6.2 재조회

이미 데이터가 화면에 있는 상태에서 재조회할 때는 다음과 같이 처리한다.

- 기존 소스와 보유 데이터 수치를 유지한다.
- 새로고침 버튼 아이콘을 회전시킨다.
- 목록 영역에 `aria-busy=true`를 적용한다.
- 응답 완료 후 새 데이터로 교체한다.
- 로딩 중 목록을 비우지 않는다.

### 6.3 실패 표시

- 로딩 실패를 빈 데이터로 표현하지 않는다.
- 기존 데이터가 있으면 기존 데이터를 유지하고 오류 안내를 별도로 표시한다.
- 기존 데이터가 없으면 오류 문구와 다시 시도 버튼을 표시한다.

### 6.4 채널·키워드 탭과 수집 현황

- `/sources`와 `/keywords` 상단에 `채널 | 키워드` 탭을 표시한다.
- 채널 탭에는 채널만, 키워드 탭에는 키워드만 표시한다.
- 행의 `구분`, `보유 데이터`, `이번 수집` 열을 제거한다.
- `수집 현황` 한 열에 영상과 댓글을 두 줄로 표시한다.
- 채널 영상은 `영상 N/M개 (P%)` 형식을 사용한다.
- 키워드 영상은 전체 모집단을 확정할 수 없으므로 `영상 N개 · 전체 미확인`으로 표시한다.
- 댓글 전체값은 수집된 영상의 최신 공개 댓글 수 합계를 사용하여 `댓글 B/M개 (P%)`로 표시한다.
- 저장 수가 최신 공개 수보다 많아도 비율은 100%를 넘기지 않는다.

### 6.5 수집 기록 문구

- 상태 화면의 실패 기록 카드 제목을 `수집 기록`으로 표시한다.
- 삭제 확인 문구는 `현재 표시된 수집 기록을 삭제할까요?`로 표시한다.
- 삭제 완료 알림은 `수집 기록이 삭제되었습니다.`로 표시한다.

## 7. 상태 표시

채널 소스에는 다음 정보를 표시한다.

- 저장된 고유 영상 수
- 채널이 공개한 영상 수
- 과거 누락 보정 필요 여부
- 이번 실행에서 확인한 페이지 수
- 이번 실행에서 발견한 신규 영상 수
- 현재 최신 조회 또는 과거 보정 단계

키워드 소스에는 다음 정보를 표시한다.

- 저장된 고유 영상 수
- 이번 실행에서 확인한 페이지 수
- 이번 실행에서 발견한 신규 영상 수
- 설정된 `maxPagesPerRun`

키워드에는 `전체 수집률` 또는 `100% 완료`를 표시하지 않는다.

## 8. 분석 키워드 품사 제한

### 8.1 추출 대상

분석 화면의 `topWords` 키워드는 Kiwi 형태소 분석 결과 중 다음 품사만 집계한다.

- `NNG`: 일반명사
- `NNP`: 고유명사

현재 포함되는 동사 어간 및 동사 원형은 제외한다.

- `VV` 계열을 집계하지 않는다.
- 동사 뒤에 `다`를 붙여 만든 표시용 원형을 생성하지 않는다.
- 형용사, 부사, 조사, 어미 등 나머지 품사도 기존처럼 제외한다.
- 불용어 필터와 빈도순 정렬 방식은 유지한다.

예시는 다음과 같다.

```text
입력: 영화를 보고 배우의 연기를 이야기했다
포함: 영화, 배우, 연기
제외: 보다, 이야기하다
```

### 8.2 적용 범위

명사 전용 필터는 동일한 `topWords` 생성 함수를 사용하는 다음 분석 결과에 공통 적용한다.

- 소스 분석 키워드
- 전체 분석 화면의 상위 키워드
- 메모리 저장소와 PostgreSQL 저장소에서 생성하는 결정적 분석 결과

화면에서만 동사를 숨기지 않고 분석 결과 생성 단계에서 제외한다.

### 8.3 기존 분석 결과 갱신

기존에 저장된 분석 결과에는 동사가 포함되어 있으므로 코드 변경만으로는 과거 결과가 즉시 바뀌지 않을 수 있다.

- 결정적 분석 파이프라인 버전을 올린다.
- 기존 소스와 수집 대상의 분석 결과를 새 버전으로 다시 생성한다.
- 재생성 중에는 기존 결과를 유지하거나 `분석 갱신 중` 상태를 표시한다.
- 새 분석이 완료되면 명사 전용 결과로 교체한다.
- 원본 댓글과 영상 데이터는 변경하지 않는다.

## 9. 구현 범위

### Worker

- 채널 페이지 결과를 소스별 Video ID 집합과 비교
- 채널 공개 영상 수와 소스별 고유 ID 수를 이용한 보정 활성화 조건 추가
- 채널 누락 보정 페이지 제한 및 체크포인트 처리
- 키워드 결과를 소스별 Video ID 기준으로 멱등 처리
- 키워드 체크포인트를 동일 작업 재시도 범위로 제한

### API 및 저장소

- 소스별 고유 Video ID 수 조회 기능 사용 또는 보완
- 작업 진행 상태에 확인 페이지 수와 신규 발견 수 노출
- 채널 누락 보정 상태 노출

### Web

- 최초 소스 로딩 스피너
- 재조회 아이콘 회전 및 `aria-busy`
- 로딩 중 빈 상태 억제
- 채널 누락 보정 상태 표시
- 키워드에 부정확한 전체 완료율을 표시하지 않도록 수정
- 채널·키워드 탭 분리 및 행의 구분 칩 제거
- 보유 데이터와 이번 수집 열을 `수집 현황`으로 통합
- 영상·댓글 수집/공개 수와 비율 표시
- 상태 화면의 수집 기록 및 삭제 완료 문구 변경

### Analysis

- `topWords` 형태소 필터를 `NNG`, `NNP`로 제한
- `VV` 동사 원형 생성 로직 제거
- 명사 빈도, 불용어, 정렬 규칙에 대한 회귀 테스트 추가
- 분석 파이프라인 버전 갱신 및 기존 분석 결과 재생성

## 10. 검증 시나리오

### 채널

1. 공개 영상 100개, 저장된 고유 ID 30개
2. 최신 페이지 10개가 모두 기존 ID
3. 첫 페이지에서 종료하지 않고 다음 페이지를 조회하는지 확인
4. 다음 페이지의 신규 ID만 작업으로 등록되는지 확인

### 중간 실패

1. 채널 보정 중 3페이지까지 성공
2. 4페이지에서 provider 오류 발생
3. 동일 작업 재시도 시 마지막 성공 체크포인트 이후를 처리하는지 확인
4. 앞 페이지의 영상이 중복 저장되지 않는지 확인

### 삭제 및 순서 변경

1. provider 결과에서 기존 영상 일부가 사라지거나 순서가 변경됨
2. 기존 저장 영상을 자동 삭제하지 않는지 확인
3. 새로 나타난 Video ID만 추가되는지 확인

### 키워드

1. 서로 다른 페이지에 동일 Video ID가 포함됨
2. ID가 한 번만 저장되고 작업도 한 번만 생성되는지 확인
3. 다음 자동 실행이 이전 검색 토큰이 아니라 최신 결과부터 시작하는지 확인
4. 검색 결과 개수를 전체 완료율로 표시하지 않는지 확인

### 로딩 UI

1. 느린 네트워크에서 최초 목록 로딩
2. 빈 목록 문구나 `0개` 대신 스피너가 표시되는지 확인
3. 재조회 중 기존 목록이 유지되는지 확인
4. 실패 시 빈 데이터로 오인되지 않는지 확인

### 소스 표

1. 채널 탭에 키워드 행이 표시되지 않는지 확인
2. 키워드 탭에 채널 행이 표시되지 않는지 확인
3. 구분 열이 제거되고 수집 현황 열만 표시되는지 확인
4. 채널 영상과 댓글이 `수집/전체 · 비율`로 표시되는지 확인
5. 키워드 영상에 부정확한 전체 비율이 표시되지 않는지 확인
6. 수집 기록 삭제 후 `수집 기록이 삭제되었습니다.`가 표시되는지 확인

### 분석 키워드

1. `영화를 보고 배우가 연기했다`를 분석
2. `영화`, `배우`, `연기`가 포함되는지 확인
3. `보다`, `연기하다` 같은 동사가 제외되는지 확인
4. 일반명사와 고유명사의 빈도순 정렬이 유지되는지 확인
5. 기존 분석 결과가 새 파이프라인 버전으로 재생성되는지 확인
6. 분석 재생성 과정에서 원본 영상과 댓글 데이터가 변경되지 않는지 확인

## 11. 완료 기준

- 채널의 과거 누락 보정이 공개 영상 수보다 소스별 고유 ID 수가 적을 때만 실행된다.
- 채널의 페이지별 신규 여부는 Video ID로 판단된다.
- 키워드 검색은 `maxPagesPerRun` 범위에서 Video ID 기반으로 멱등 처리된다.
- 키워드 검색 결과 개수가 완료율이나 과거 전체 보정 기준으로 사용되지 않는다.
- 로딩 중 빈 목록 또는 `0개`가 먼저 표시되지 않는다.
- 분석 키워드에는 일반명사와 고유명사만 포함된다.
- 기존 분석 결과도 재생성되어 동사가 남아 있지 않는다.
- 채널과 키워드가 탭별 테이블로 분리되고 수집 현황 열로 단순화된다.
- 수집 기록 삭제 안내가 요청된 문구로 표시된다.
- 자동 6시간 실행과 즉시 수동 재수집 동작은 유지된다.
